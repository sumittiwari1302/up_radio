# UP Radio • उत्तर प्रदेश रेडियो

A live radio web app for **Uttar Pradesh** — every free-to-air [Akashvani / All India Radio](https://akashvani.gov.in) station broadcasting from UP, plus community/campus and online stations with a free web stream, and a full directory of commercial FM frequencies. A small Node server serves the channel catalog over REST and the live listener/stream status over a WebSocket.

> First version: simple UI, runtime-fetched catalog, real WebSocket layer.

## Catalog (112 stations, 54 playable)

`channels.json` is generated by merging three public sources and grouping stations:

| Group | Stations | Playable | Source |
|-------|----------|----------|--------|
| PUBLIC / AKASHVANI | 30 | 16 | [asiawaves.net](https://www.asiawaves.net/india/uttar-pradesh-radio.htm) frequencies + [codito/akashvani](https://github.com/codito/akashvani) streams |
| COMMUNITY / CAMPUS RADIO | 38 | 3 | asiawaves frequencies + public web streams |
| ONLINE / WEB RADIO | 2 | 2 | [onlineradiofm.in](https://onlineradiofm.in/uttar-pradesh) |
| PRIVATE / COMMERCIAL FM | 42 | 33 | asiawaves frequencies + network online feeds |
| **Total** | **112** | **54** | |

**Uttar Pradesh only.** Every free-to-air UP station from the asiawaves directory is present, plus the
national Akashvani services that actually reach UP — **Vividh Bharati** (relayed across UP),
**Gyan Vani** (Agra/Kanpur/Lucknow/Prayagraj/Varanasi) and **FM Rainbow** (Lucknow/Kanpur). FM Gold
is Delhi-only, so it is excluded.

Playable streams (all verified live): 13 Akashvani city stations + FM Rainbow Lucknow/Kanpur +
Vividh Bharati; `Aap ki Awaaz` (Agra), `Radio Pragya` (Padrauna), `Radio Noida`,
`Radio Aashiqanaa` (Kanpur), `Madhur Sangeet` (Noida); and the free online feeds of the commercial
networks attached to each UP city that carries them — Big FM, Radio City, Radio Mirchi, Fever FM,
Mirchi Love, Red FM, Radio Mantra. Entries with no public stream (Radio Tadka, HINT, Current,
City FM, Gyan Vani, and most campus/community radios) are shown as **directory** rows with their
real frequencies.

Frequencies follow the asiawaves/MIB directory (FM as MHz, MW as kHz). Example: Akashvani Mathura is
**FM 102.2 MHz** (the old 1584 kHz MW relay is no longer listed as its current service).

## Quick start

```bash
npm install
npm run build:catalog   # optional: regenerate channels.json from all sources
npm start               # http://localhost:4173
```

Then open <http://localhost:4173>.

- `npm run dev` — start with auto-reload (`node --watch`)
- `npm run refresh` — rebuild `channels.json` and re-probe streams
- `PORT=8080 npm start` — run on a different port

## How it is built

```
up-radio/
├─ channels.json          generated catalog (snake_case, source of truth at runtime)
├─ server/
│  ├─ build-catalog.js    merge asiawaves + akashvani + onlineradiofm → channels.json
│  ├─ catalog.js          load channels.json at runtime (rebuild if missing)
│  ├─ refresh.js          `npm run refresh` one-shot rebuild
│  └─ index.js            Express REST API + WebSocket + static hosting
└─ public/
   ├─ index.html          UI
   ├─ app.js              catalog fetch, HLS playback, WebSocket client
   └─ style.css
```

The browser **fetches the catalog at runtime** from `/api/channels` (never hard-coded), then plays
each stream with [hls.js](https://github.com/video-dev/hls.js) (HLS) or a plain `<audio>` element
(icecast/AAC). The UI filters by **PLAYABLE / ALL / AKASHVANI / COMMUNITY / ONLINE / PRIVATE FM**;
non-streamable stations are disabled and labelled `ON AIR • NO WEB STREAM`.

## REST API

| Method | Path | Description |
|--------|------|-------------|
| `GET`  | `/api/health` | Liveness + listener count + playable station count |
| `GET`  | `/api/channels` | Full UP catalog (`station_dashboard.groups[].channels[]`) |
| `POST` | `/api/channels/refresh` | Rebuild from upstream, rewrite `channels.json`, re-probe streams |
| `GET`  | `/api/status` | Current reachability of the playable streams |

## WebSocket

Connect to `ws://<host>/ws`. The server pushes a live feed and also accepts a few client commands.

**Server → client**

```jsonc
{ "type": "welcome",  "clientId": "c1", "listeners": 3, "nowPlaying": [], "statuses": {}, "serverTime": 0 }
{ "type": "presence", "listeners": 3, "nowPlaying": [{ "stationId": "all-india-radio-lucknow-lucknow", "listeners": 2 }], "serverTime": 0 }
{ "type": "status",   "statuses": { "all-india-radio-lucknow-lucknow": { "online": true, "checkedAt": 0, "latencyMs": 120 } }, "serverTime": 0 }
{ "type": "pong",     "serverTime": 0 }
```

**Client → server**

```jsonc
{ "type": "now-playing", "stationId": "all-india-radio-lucknow-lucknow" }  // tune in
{ "type": "stopped" }                                                        // tune out
{ "type": "ping" }                                                           // keepalive
{ "type": "request-status" }                                                 // ask for a fresh status snapshot
```

Behaviour:
- **Presence** — every connect/disconnect/tune broadcasts the current listener count and which station each listener is on.
- **Stream status** — the server probes the 20 playable streams every 2 minutes and broadcasts reachability; a stream is only marked offline after two consecutive failures (no flapping).
- **Heartbeat** — ping/pong every 30 s drops dead sockets with `unref()`ed timers.
